# Transaction

## 필드 (`transactionSchema`)

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| `type` | ✓ | `INCOME` / `EXPENSE` |
| `amount` | ✓ | 정수 1 ~ 10억 |
| `occurredOn` | ✓ | 유효한 `YYYY-MM-DD` |
| `categoryId` | ✓ | 아래 카테고리 규칙 |
| `merchant` 거래처 | | ≤ 100자 |
| `item` 구매 항목 | | ≤ 100자 |
| `purpose` 구매 이유 | | ≤ 200자 |
| `paymentMethod` 결제 수단 | | enum 또는 null |
| `memo` 메모 | | ≤ 1000자 |

선택 텍스트는 trim 후 빈 값이면 `null` (`optionalText`).
`recurringExpenseId`는 고정지출이 자동 생성한 거래에만 있다. 폼에서 설정하지 않는다.

## 카테고리 규칙 (서버 검증)

- 카테고리가 존재해야 한다: `"카테고리를 찾을 수 없습니다"`
- 카테고리 유형 = 거래 유형: `"거래 유형과 카테고리 유형이 일치하지 않습니다"`
- 보관된 카테고리는 쓸 수 없다: `"보관된 카테고리는 사용할 수 없습니다"`
  - 예외: 수정 시 기존 카테고리가 보관됐으면 그대로 유지 가능

## 생성·수정·삭제

- 동시 수정은 마지막 저장이 이긴다 (버전 체크 없음).
- 이미 삭제된 거래 수정·삭제: `"이미 삭제되었거나 존재하지 않는 거래입니다"` (`TX_NOT_FOUND`) → 클라이언트가 다이얼로그를 닫는다.
- 삭제는 하드 삭제. 고정지출이 만든 거래를 지워도 다시 생성되지 않는다 ([recurring.md](recurring.md)).
- 복제: 수정 다이얼로그의 "복제"(삭제 옆) → 같은 다이얼로그가 "거래 추가" 폼으로 바뀐다. 유형·금액·카테고리·거래처·구매 항목·구매 이유·결제 수단·메모를 원본 값으로 채우고 날짜는 오늘. 원본 카테고리가 보관됐으면 카테고리는 비운다. 고정지출 연결(`recurringExpenseId`)은 복사하지 않는다. 일반 생성 모드라 최근 거래 칩·거래처 자동 채우기도 동작하고, 저장은 사용자가 한다.

## 일괄 편집 (`/transactions`, `TransactionList`)

목록에서 여러 거래를 선택해 카테고리를 한 번에 바꾸거나 삭제한다.

- 선택: PC 표는 체크박스 열(머리글 = 전체 선택/해제), 모바일 카드는 "선택"으로 선택 모드에 들어가 카드를 누르면 선택/해제. "완료" = 선택 해제 + 모드 종료. PC·모바일이 같은 선택 상태를 쓴다(선택이 있으면 모바일도 선택 모드).
- 처리 대상은 현재 목록(현재 페이지)에 보이는 선택 거래뿐이다. 필터 변경·페이지 이동·새로고침으로 목록에서 빠진 거래는 선택에서도 빠진다. PC 머리글 체크박스와 모바일 "전체 선택"도 현재 페이지만 선택한다.
- 동작 바는 목록 위에 항상 있다(선택 0건이면 안내 문구). 첫 선택 때 목록이 밀려 오선택되지 않게 하기 위함.
- 카테고리 변경
  - 선택이 모두 같은 유형일 때만. 수입·지출이 섞이면 PC는 버튼 비활성 + "수입·지출이 섞여 있어 카테고리를 바꿀 수 없습니다", 모바일은 흐린 아이콘을 누르면 같은 문구 토스트.
  - 대상은 그 유형의 활성 카테고리. 서버도 검증한다: 없는 카테고리·보관 카테고리·유형 불일치(하나라도 있으면 아무것도 안 바꿈)는 단건과 같은 문구로 거부. 단건 수정의 "현재 보관 카테고리 유지" 예외는 없다. 보관 카테고리에 있던 거래를 활성 카테고리로 옮기는 것은 허용.
  - 고정지출이 만든 거래도 바꿀 수 있고 `recurringExpenseId`는 유지된다. 고정지출 항목의 카테고리는 바뀌지 않으므로 이후 생성되는 거래는 원래 카테고리다.
- 삭제: 확인 후 하드 삭제. 수입·지출이 섞여도 된다.
- 한 번에 최대 5,000건 (`"한 번에 최대 5,000건까지 처리할 수 있습니다"`). 일부가 이미 삭제됐으면 남은 것만 처리하고 실제 건수를 알린다. 전부 없으면 `TX_NOT_FOUND`.

## 입력 UX (거래 폼)

순서: 유형 토글(기본 지출, 바꾸면 카테고리 초기화) → (생성 모드) 최근 거래 칩 → 금액(자동 포커스) → 카테고리(최근 사용 칩 최대 5개 + Select) → 날짜(기본 오늘 / 진입 경로 기준) → "상세 입력" 접힘 영역(거래처·구매 항목·구매 이유·결제 수단·메모).

- 최근 카테고리: 해당 유형에서 최근 거래 순, 중복 없이, 보관 카테고리 제외 (`getRecentCategoryIds`).
- 최근 거래 칩 (`getRecentTransactionPresets` → `pickRecentPresets`): 생성 모드에서만, 현재 유형 최대 5개. 직접 입력한 거래(`recurringExpenseId` 없음)·활성 카테고리만, 최근 100건을 `occurredOn desc, createdAt desc`로 보고 유형·카테고리·금액·거래처·구매 항목·결제 수단이 같으면 하나로 합친다. 라벨 `거래처 ?? 구매 항목 ?? 카테고리` + 금액.
  - 누르면 금액·카테고리·거래처·구매 항목·결제 수단을 덮어쓴다(이미 입력한 값 포함). 날짜·구매 이유·메모·유형은 그대로. 거래처·구매 항목·결제 수단이 있으면 "상세 입력"을 펼친다. 저장은 사용자가 한다.
- 거래처 자동완성 (`getMerchantSuggestions` → `pickMerchantSuggestions`): 거래처 입력의 `<datalist>`에 현재 유형 거래처 최대 100개(생성·수정 모드 모두). 직접 입력한 거래(`recurringExpenseId` 없음)·활성 카테고리·거래처 있는 거래만. 거래처는 건수 → 최근 거래일 → 이름 순.
  - 거래처별 제안 값: 카테고리는 최다 건수(동률은 최근 거래일 → id 순), 결제 수단은 null 제외 최다 건수(동률은 최근 거래일 → `PAYMENT_METHODS` 순, 전부 null이면 없음).
  - 생성 모드에서만, 거래처 입력이 바뀔 때마다 입력값(trim)과 정확히 일치하는 제안으로 카테고리·결제 수단을 채운다. 비어 있거나 직전에 자동으로 채운 값인 필드만 바꾸고(일치가 없으면 자동 값을 비움), 사용자가 고른 값은 그대로 둔다. 접두어가 겹치는 거래처("GS" → "GS25")·한글 조합 중간 값이 남지 않게 하기 위함.
- Select 옵션: 현재 유형의 활성 카테고리 + (수정 시) 보관된 현재 카테고리.

## 목록 조회 (`/transactions`, `listTransactions`)

| 조건 | 규칙 |
| --- | --- |
| 기간 | 월별(선택 월) / 기간(`from`~`to`, 양끝 포함) / 전체 기간(`range=all`, 조건 없음). 기간 날짜는 `isValidPeriodDate`(유효 날짜, 연도 1900~9998)이고 `from <= to`여야 하며, 아니면 무시하고 월별 |
| 유형 | 전체 / 수입 / 지출 |
| 카테고리 | id 일치 (보관 카테고리 포함) |
| 결제 수단 | 값 일치, "미지정"(`none`)은 결제 수단 없는 거래. 유형 필터와 독립 |
| 검색 `q` | 거래처·구매 항목·메모 중 하나에 포함, 대소문자 무시 |
| 정렬 | `occurredOn` → `createdAt` → `id`, 모두 같은 방향, 기본 최신순(`desc`). `id`는 같은 시각 행의 페이지 경계를 고정한다 |
| 페이지 | 100건씩(`TRANSACTION_PAGE_SIZE`), `?page=N`(`paginate`). 1페이지뿐이면 이동 UI 없음. 목록 아래 `이전 · N / M · 다음`. 마지막 페이지를 넘으면 마지막 페이지를 보여 준다(URL 유지). 필터 변경·월 이동 시 1페이지 |
| 합계 | 필터 결과 전체(페이지와 무관)의 수입·지출 합계 표시 (`summarizeTransactions`) |
| 빈 상태 | 필터가 있으면 "조건에 맞는 거래가 없습니다" + 필터 초기화(월·기간 파라미터는 유지), 없으면 "이 달에는 거래가 없습니다" / "이 기간에는 거래가 없습니다" / "거래가 없습니다"(전체 기간) |

### 기간 선택 UI (`TransactionFilters`)

- 필터 바 맨 앞 `[월별|기간|전체 기간]` 토글. 월별 = `from`·`to`·`range` 제거(`month` 유지), 기간 = 현재 `month`의 1일~말일로 시작, 전체 기간 = `range=all`.
- 기간 모드에서만 시작일·종료일 입력. 입력값은 로컬 상태로 두고 `isValidPeriodDate`를 통과할 때만 URL에 반영한다(연도 입력 중간값이 URL로 가지 않게). 반영 시 URL의 반대쪽 날짜를 넘으면 반대쪽도 같은 날로 맞춘다.
- 월별이 아니면 헤더에 `MonthSwitcher` 대신 기간 문구("2026.01.01 ~ 2026.10.26" / "전체 기간"), 모바일 카드 목록 날짜 제목에 연도를 붙인다(`showYear`).
- FAB 기본 날짜는 기간 모드에서도 URL의 `month` 기준이다.

## CSV 내보내기·가져오기 (`src/lib/transaction-csv.ts`)

거래 내역 화면의 "CSV" 메뉴. 형식은 내보내기와 가져오기가 같다.

- 열: `날짜, 유형, 금액, 카테고리, 거래처, 구매 항목, 구매 이유, 결제 수단, 메모`. 날짜는 `YYYY-MM-DD`, 유형·결제 수단은 화면 문구(`수입`/`지출`, `신용카드` 등).
- 내보내기: UTF-8 BOM + CRLF (엑셀 한글 호환).
  - 현재 목록: 화면 필터(기간·유형·카테고리·결제 수단·검색·정렬) 그대로 → 월별 `moneybook-<YYYY-MM>.csv`, 기간 `moneybook-<from>_<to>.csv`, 전체 기간 `moneybook-all-filtered-<오늘>.csv`
  - 전체: 모든 거래를 날짜 오름차순 → `moneybook-all-<오늘>.csv`
  - 0건이면 파일 대신 "내보낼 거래가 없습니다" 안내
- 가져오기
  - 헤더는 9개 이름이 정확히 일치해야 한다 (순서 무관). 없는·알 수 없는·중복 열은 파일 오류. 헤더 끝의 빈 칸(엑셀이 남기는 `,,`)은 무시한다.
  - 모든 칸은 trim. 빈 행은 건너뛴다. 헤더보다 많은 칸에 값이 있으면 행 오류.
  - 카테고리는 (유형, 이름)으로 찾는다. 없는 카테고리는 만들지 않고 오류, 보관된 카테고리도 오류.
  - 각 행은 `transactionSchema`로 검증한다. 오류 행이 하나라도 있으면 **아무것도 등록하지 않는다** (행 번호는 헤더 = 1행).
  - 한 번에 5,000건 / 800KB까지. 등록은 한 트랜잭션.
  - 가져온 거래는 고정지출과 연결되지 않는다 (`recurringExpenseId` 없음).
